## 2. 핵심 모듈 상세

### 2.1 `src/feature_extractor.py` — 피처 추출

BIM(Revit) 패밀리 JSON을 머신러닝 입력 벡터로 변환하는 모듈. 도메인의 출발점이다.

**주요 함수**

- `extract_features(data: dict) -> dict` : JSON dict → 피처 딕셔너리
- `extract_features_from_file(json_path) -> dict` : 파일 경로 버전
- `NUMERIC_FEATURE_COLS` : 학습에 사용하는 24개 수치 피처 컬럼 목록
- `FEATURE_GROUPS` : Ablation Study용 피처 그룹(geometry/connector/metadata)

**추출 피처 (3계열, 총 24개)**

| 계열 | 피처 | 설명 |
|------|------|------|
| **메타데이터(2)** | `meta_max_size_mm`, `meta_min_size_mm` | 최대/최소 구경 (mm) |
| **형상(12)** | `geo_surface_area`, `geo_volume`, `geo_solid_count`, `geo_face_count`, `geo_bbox_x/y/z`, `geo_bbox_diag`, `geo_aspect_xy/xz/yz`, `geo_compactness` | 표면적·체적·솔리드/Face 수·바운딩박스·종횡비·밀집도 |
| **커넥터(10)** | `conn_count`, `conn_radius_mean/std/max/min/range`, `conn_distance`, `conn_angle_deg`, `conn_same_axis`, `conn_is_inline` | 커넥터 수·반경 통계·커넥터 간 거리/각도·동축/인라인 여부 |

**단위 변환** : Revit 내부 단위(feet) → 미터계
- 길이 × 0.3048, 면적 × 0.3048², 부피 × 0.3048³

**도메인 핵심 로직**
- 바운딩박스는 모든 솔리드의 Face → EdgeLoop → Tessellate 점을 순회해 min/max로 산출
- 커넥터 2개 이상일 때 두 커넥터의 방향 벡터 사잇각으로 `same_axis`(평행, <10°·>170°), `is_inline`(역방향, >170°) 판정 → 직관(inline)/엘보 구분의 핵심 단서

### 2.2 `src/skey_mapper.py` — SKEY 레이블 매핑

`symbol.xml`의 SKEY(심볼 키)를 학습 레이블(컴포넌트 그룹·밸브 타입)로 변환하는 규칙 엔진.

**클래스 체계**

- `GROUP_CLASSES` (15개) : VALVE, FITTING, FLANGE, GASKET, SLEEVE, SUPPORT, INSTRUMENT, FLEXIBLE_JOINT, ACCESSORY, OLET, CAP, COUPLING, TRAP, PIPE, UNKNOWN
- `VALVE_TYPE_CLASSES` (22개) : BALL, GATE, GLOBE, BUTTERFLY, CHECK, CONTROL, SAFETY, PRESSURE_REDUCING, DIAPHRAGM, COCK, NEEDLE, PLUG, SLIDE, THREE_WAY, FOUR_WAY, KNIFE_GATE, BASIC, BREATHER, ANGLE, AUTO, UNKNOWN, NON_VALVE
- `GROUP_TO_INT`/`INT_TO_GROUP`, `VTYPE_TO_INT`/`INT_TO_VTYPE` : 정수 인코딩 매핑

**매핑 우선순위 (`_derive_labels`)**

1. **SKEY 오버라이드** (`_SKEY_OVERRIDE`) — 접두어 정확/시작 매칭 (예: EX→FLEXIBLE_JOINT, SLVE→SLEEVE)
2. **PCF_Identification 기반** (`_PCF_TO_GROUP`) — VALVE/FLANGE/ELBOW/TEE 등
   - MISC-COMPONENT 등 모호 항목은 `_refine_misc()`로 Description 기반 세분화
3. **Category 텍스트 fallback** — 문자열 포함 검사
4. 밸브 그룹이면 `_derive_valve_type()`로 `_SKEY_TO_VALVE_TYPE` 매핑 (VB→BALL, VT→GATE 등)

**주요 함수**
- `parse_symbol_xml(xml_path) -> {skey: SkeyInfo}` : symbol.xml 파싱
- `get_labels_from_skey(skey_value, skey_map) -> dict` : SKEY 값 → 레이블 (정확→prefix→규칙 fallback)

---

### 2.3 `src/label_extractor.py` — 파일명 기반 레이블 (fallback)

xlsx/CSV 레이블이 없을 때 **FamilyName/파일명의 텍스트 패턴**으로 레이블을 추정하는 정규식 규칙 엔진.

- `_GROUP_RULES` : "BALL VALVE"→VALVE, "GASKET"→GASKET, "PIPE SHOE"→SUPPORT 등 (구체적 패턴 우선)
- `_VALVE_TYPE_RULES` : 밸브 세부 타입 정규식
- `extract_component_group(name)`, `extract_valve_type(name)`, `extract_labels(name)`

> 이 모듈의 클래스 체계는 10개 그룹·11개 밸브타입으로 `skey_mapper`보다 단순하다(초기 버전). v1의 마지막 안전망 역할.

---

### 2.4 데이터 로더 — `data_loader.py` (v1) / `data_loader_csv.py` (v2)

| | v1 `data_loader.py` | v2 `data_loader_csv.py` |
|---|---|---|
| 입력 데이터 | 단일 폴더의 `*.json` | `TrainingModel/{모델}/*.json` |
| 레이블 출처 | `학습용레이블_정답.xlsx` (+ 파일명 fallback) | `전문가_정의_csv/{모델}.csv` |
| 레이블 매핑 | `LabelRegistry` → SKEY → 그룹 | `_find_skey` → SKEY → 그룹 |
| 제외 처리 | — | `NC**`(미정), `_P**`(파이프) 제외 |
| 반환 | `DataFrame` | `(DataFrame, nc_samples)` |

**공통 산출 컬럼** : `source_file`, `meta_*`, 24개 수치 피처, `skey`, `component_group`, `valve_type`, `is_valve`, `group_label`(정수), `vtype_label`(정수)

**v2 매칭 로직 (`_find_skey`)** : "FamilyName: TypeName" 조합 → 정확 매칭 → 정규화(공백·특수문자 제거) 매칭 → 부분 매칭 순으로 SKEY를 찾는다.

---

### 2.5 `src/label_loader.py` — xlsx 정답 레이블 로더 (v1)

`학습용레이블_정답.xlsx`를 읽어 (FamilyName, TypeName) → 레이블 lookup을 구성하는 `LabelRegistry` 클래스.

- 컬럼 자동 탐지 (`ProductCode`/`SKY` 후보군, 대소문자·한글 무관)
- `_parse_product_code` : "패밀리명: 타입명" 분리
- `get_labels(family, type)` : 정확→부분→family 매칭 다단계 조회
- `get_labels_from_filename(stem)` : 파일명에서 family/type 분해 후 조회
- `extract_labels_with_fallback(...)` : registry 우선, 실패 시 `label_extractor` fallback

---

### 2.6 학습 모듈 — `train_group.py` / `train_type.py` (v1)

**`train_group_classifier(df, ...)`**
- 모델 : LightGBM (`LGBM_PARAMS`, 소규모 데이터 최적화 — num_leaves=8, max_depth=4, 강한 정규화, class_weight=balanced)
- 교차검증 : 샘플 < 30 또는 `loo` → LeaveOneOut, 아니면 StratifiedKFold-5
- 절차 : fold별 StandardScaler 학습 → 모델 학습 → 예측 누적 → CV 정확도/분류리포트
- 저장 : 전체 데이터 재학습 후 `group_classifier.pkl`, `group_scaler.pkl`, `group_features.pkl`
- `run_ablation_study(df)` : geometry/connector/metadata 조합별 정확도 비교

**`train_type.py`** : VALVE 그룹 샘플만으로 밸브 타입 분류기 학습 (구조 동일)

> v2는 별도 학습 모듈을 쓰지 않고 `run_pipeline_v2.py` 안에 학습 로직을 내장한다(아래 3.2 참조).

---

### 2.7 `src/predict.py` — 추론기

**`PipeComponentPredictor` 클래스**

- 생성자에서 `model_dir`의 그룹 분류기(필수)·밸브 타입 분류기(선택)를 로드
- `predict_features(features)` : 피처 dict → 그룹 분류 → (VALVE면) 밸브 타입 분류 → 신뢰도 기반 검토 여부 산출
- `predict_file(json_path)` : JSON 1개 → 피처 추출 후 예측
- `predict_batch(json_dir, output_csv)` : 폴더 일괄 예측 + CSV 저장 + 요약

**신뢰도 규칙** : ≥0.90 auto / 0.70~0.90 review / <0.70 unknown
→ `review_required`, `review_reason` 으로 사람 검토가 필요한 항목을 표시 (Human-in-the-loop)

## 3. 엔트리포인트(파이프라인)

### 3.1 `run_pipeline.py` (v1)

```
[1] load_dataset (JSON+xlsx)  →  피처통계/레이블분포/매칭결과 CSV
[2] train_group_classifier    →  그룹 분류기
[3] train_type_classifier     →  밸브 타입 분류기
[4] generate_evaluation_report
[5] (옵션) Ablation Study
[6] (옵션) 배치 추론
```
CLI 옵션: `--data_dir`(필수), `--model_dir`, `--ablation`, `--infer`, `--output_csv`

### 3.2 `run_pipeline_v2.py` (v2, 권장)

```
[1] load_dataset_csv (TrainingModel + 전문가 CSV)  →  NC 분리, dataset.csv
[2] 피처 행렬 준비 (NUMERIC_FEATURE_COLS)
[3] StratifiedKFold(5) 학습  →  fold별 정확도
[4] 전체 데이터 최종 모델 학습  →  models_v2/*.pkl
[5] 평가 리포트  →  classification_report / confusion_matrix / feature_importance / fold_accuracies CSV
```

**v2 LightGBM 파라미터(요지)** : num_class=15, num_leaves=31, max_depth=6, learning_rate=0.05, n_estimators=300, class_weight=balanced, early_stopping(30). v1 대비 데이터가 많아 모델 용량을 키운 설정.

## 5. 핵심 설계 포인트 (논문 관점)

1. **3계열 피처 설계** — 도면(2D) OCR이 아니라 BIM 3D 형상·커넥터·메타데이터에서 직접 피처를 추출해 컴포넌트를 식별한다. 특히 커넥터 기하(개수·반경·동축/인라인)가 밸브·피팅 구분의 핵심 단서.
2. **레이블 다단계 매핑** — symbol.xml SKEY 체계를 표준 레이블로 정규화(`skey_mapper`)하고, 전문가 CSV → xlsx → 파일명 규칙 순의 fallback 으로 레이블 커버리지를 확보.
3. **소규모 → 확장 데이터 대응** — v1은 LeaveOneOut-CV(55샘플), v2는 Stratified 5-Fold(181모델)로 데이터 규모에 맞춰 교차검증 전략을 전환.
4. **Human-in-the-loop** — 신뢰도 임계값(0.90/0.70)으로 자동/검토/미지를 구분, 검증 서버(`ai_validator`)로 사람이 결과를 확인.
5. **연동성** — FastAPI REST로 C#/DevExpress WinForm 등 외부 애플리케이션과 분리·연동 가능한 구조.
